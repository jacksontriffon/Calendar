# @calendar/app

Expo app (iOS, Android, web) for Calendar. Expo SDK 58, TypeScript, Expo Router.
Architecture and phases: [`docs/expo-plan.md`](../../docs/expo-plan.md). This
folder is the Phase 0 scaffold: a route skeleton with placeholder screens, the
Supabase client, and build config. No product features yet.

## Run

From the repo root, install once (pnpm workspace, hoisted `node_modules`):

```sh
pnpm install
```

The app uses a **development client**, not Expo Go (widgets and native modules
need custom native code). Build one, then start Metro:

```sh
cd apps/app

# Local native build (needs Xcode / Android Studio):
npx expo run:ios            # or: pnpm --filter @calendar/app ios
npx expo run:android        # or: pnpm --filter @calendar/app android

# Or a cloud build with EAS (after the manual setup below):
eas build --profile development --platform ios       # add --platform android as needed
eas build --profile development-simulator --platform ios   # iOS simulator build

pnpm --filter @calendar/app start    # expo start --dev-client; open the installed dev build
pnpm --filter @calendar/app web      # web in the browser, no native build needed
```

`ios/` and `android/` are generated (`expo prebuild`) and git-ignored. Config
lives in `app.config.ts`; never edit the native folders by hand.

## Scripts

| Script | What it does |
|---|---|
| `start` | `expo start --dev-client` |
| `ios` / `android` | `expo run:ios` / `expo run:android` (native build + launch) |
| `web` | `expo start --web` |
| `typecheck` | `tsc --noEmit` |
| `lint` | `expo lint` (ESLint 9 + `eslint-config-expo`) |
| `test` | `jest` (jest-expo preset) |
| `export:web` | `expo export -p web` (static SPA in `dist/`, git-ignored) |

Typed routes are on. `.expo/types/router.d.ts` is generated by `expo start`;
run it once (or `expo customize`) for `tsc` to check `href` values strictly.

## Environment variables

Copy `.env.example` to `.env.local`:

| Variable | Purpose |
|---|---|
| `EXPO_PUBLIC_SUPABASE_URL` | Supabase project URL (local stack: `http://127.0.0.1:54321`) |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon / publishable key |

`EXPO_PUBLIC_*` is inlined into the bundle: never put secrets (service role, Google or
Anthropic keys) here. Those live in edge function secrets. Without these values the app
still builds and runs, and `src/lib/supabase.ts` logs a warning. For EAS builds, create
the same variables with `eas env:create`.

## Manual setup (not done by the scaffold)

1. **EAS project:** run `eas login` then `eas init` in this folder. It writes
   `extra.eas.projectId` (and `owner`) into the config. There is deliberately no
   projectId in the repo yet. `eas.json` already exists with `development` (dev client,
   internal), `development-simulator`, `preview` and `production` profiles, so
   `eas build:configure` is not needed.
2. **Bundle id:** `com.claudecalendar.app` (iOS `bundleIdentifier`, Android `package`) is a
   **placeholder**. The real id is an open question (plan section 9, item 9). Decide it
   before the first signed build, because it is tied to the Apple App ID, Sign in with Apple,
   App Groups, the Google OAuth client and Play listing. Change `APP_ID` in `app.config.ts`.
3. **Apple / Google sign-in:** Apple Developer team, App ID with Sign in with Apple, and a
   Google OAuth client (phase 2). `usesAppleSignIn` is already set.
4. **Supabase:** create or link a project, then fill `.env.local`.
5. **Icons and splash:** `assets/` holds Expo's default icons as placeholders (phase 9).

## Sign-in setup (phase 2)

Welcome, setup, import, Account and the re-sign-in sheet live in `src/features/{welcome,onboarding,auth}`.
What the maintainer must configure (values in `.env.example`):

- **Supabase Auth > URL configuration:** allow-list `aicalendar://auth/callback` and the web origin.
- **Apple:** Services ID + key in Supabase's Apple provider (web and Android use the OAuth redirect); iOS uses the
  native sheet (`usesAppleSignIn` is set) and `signInWithIdToken`.
- **Google:** a web OAuth client (Supabase's Google provider), an iOS client and an Android client (package + SHA-1).
  Set `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` and `GOOGLE_IOS_URL_SCHEME` (reversed iOS
  client id, read by `app.config.ts`). In Supabase's Google provider list the iOS + web client ids as authorized and
  enable "Skip nonce checks" (the native library cannot pass a nonce).
- Native sign-in needs a dev-client build; it cannot run in Expo Go or on web.


## Notes

- **Monorepo:** the repo uses `node-linker=hoisted` (`.npmrc`). Expo SDK 52+ detects
  workspaces, so there is no `metro.config.js`. Add one only if wiring `@calendar/core`
  needs extra `watchFolders` / resolution.
- **Session storage:** SecureStore values are size-limited and a Supabase session is bigger,
  so `secureStorage.ts` stores it in chunks. (The plan's alternative is Supabase's guide
  pattern of an encrypted AsyncStorage blob with the key in SecureStore.)
- **Web output:** `web.output = "single"` (SPA), since every screen is behind sign-in.
- **Deferred:** `@calendar/core` dependency, `react-native-mmkv`, Legend-State, Google
  Sign-In, widgets (`@bacons/apple-targets`, `react-native-android-widget`), real fonts.
